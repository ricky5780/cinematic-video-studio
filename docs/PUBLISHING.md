# 发布说明

源码包准备完成不等于 GitHub 已发布。以成功创建的仓库、远端提交及公开可见性核验为准。

## 本机已登录 GitHub CLI 时

代码附带 `publish.py`，只创建**新的公开仓库**：

```sh
python3 publish.py --owner YOUR_GITHUB_LOGIN --public
```

默认仓库名 cinematic-video-studio。要求本地 Git、GitHub CLI 与已登录会话；
登录通过 `gh auth login` 在本机完成，不把令牌发送到聊天或保存到仓库。

发布器会核验发行清单、确认登录账号、拒绝覆盖同名仓库、运行全部测试，
在干净临时 Git 仓库中仅加入发行清单列出的文件，再创建公开仓库并推送 main 与版本标签。
不使用 force push，不修改全局 Git 配置，不复制工作区里未列入清单的素材或凭证。
提交使用 GitHub no-reply 邮箱。发布完成后核验远端 SHA 和 public 状态，写 PUBLISH_RESULT.json。

若远端创建后推送失败，脚本会明确指出不完整状态，不删除远端仓库，也不谎报成功。
同名仓库存在时不会继续，需人工确认用途后通过现有仓库的正常提交流程处理。

## 连接器只能写已有仓库时

在目标账号下新建一个公开空仓库，再通过已授权连接器提交发行清单中的文件。
不要把代码塞进无关项目来绕过“新建仓库”能力缺失。

## 发布后的检查

核对 README、LICENSE、SKILL.md、脚本、测试、模板及工作流是否齐全。
核对默认分支、公开可见性、提交 SHA 和 tag。
GitHub Actions 的结果必须在远端实际运行后读取；本地测试不能代替远端绿色状态。
不上传本地 qa/、私人素材、旧聊天截图或测试时使用的本机完整路径日志。
